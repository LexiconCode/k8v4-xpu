# All opt-in ports together on vLLM 0.34 (2026-11-19)

`b70/all-034` = `b70/e2e-034` (their stack on vLLM 0.34 + sliced upload + PR3 decode kernels + multi-page S1 +
`K8V4_MTP_SHARED_DEPTH`) with every finished opt-in port cherry-picked on top. Every knob is off by default: with
all of them unset, `launch.sh` prints the same docker command as `b70/e2e-034` byte for byte (checked with
`K8V4_DRY_RUN=1`, worktree path normalised, both for the plain default and for the `K8V4_MAX_SEQS=4` /
prefix caching / util 0.96 / `XE2_KV_S1_SPLITS=32` / `K8V4_MTP_SHARED_DEPTH=3` profile). The CPU unittest suite
passes inside the 0.34 image (176 tests, 10 XPU-only skips).

`win-e2e.sh` settings: `TESTS="exact needle users prefix custom mt"`, `USERS="1 4"`, `MT_LEVELS="1 4"`,
`CONV_PER_CLIENT=1`, `SEED_BASE=20261118`, `NEEDLE="32000 120000"`, `WEDGE_SECS=240`, model pre-read, their coding
client (`bench/serve_coding.py`, 2K/8K/32K/128K, 448 tokens, 3 repeats) as the custom step. Vision on (their

## Numerics

- Knobs unset: identical command, identical ops.
- Config A changes prefill numerics (W4A8 int8 activations on attention, GDN and other linears; s4 library
  without zero points). GDN heads is bit-identical, draft last row and the memory knobs do not change outputs,
  spec decode stays lossless (the target verifies every token).
- EXACT 8/9 (the same item the base misses) and NEEDLE 6/6 at 17K and 64K.
- The harness prefix check (cold vs cold, full and partial prefix vs cold, 10 prompts): cold-vs-cold top-1 8/10,
  KL mean 0.66, max 3.99 (code 14K and 23K flip the argmax); their 0.30 base had 10/10, KL max 0.21. The
  check reports 0 cached tokens on their stack in every run, so these are run-to-run differences of two cold
  prefills, not a cache defect. Not attributed yet to a single knob (W4A8 on all linears is the likely one); it
  needs a per-knob prefix window and QualityBench before anything here is called quality-neutral.
